# Architecture

Core Metrics has one native app target and two test targets. AppKit owns the application and status item; SwiftUI supplies the selection controls and native Settings scene. Small providers own public system API calls; pure calculators own metric math. No package, general-purpose service container, repository framework, database, or networking layer is needed.

## Flow and ownership

`CoreMetricsApp.main` runs `NSApplication` and keeps `CoreMetricsAppDelegate` alive. The main-actor delegate owns `MetricsStore`, `PreferencesStore`, `LaunchAtLoginStore`, the copy writer, represented Settings scene and `StatusItemController`. It registers `CoreMetricsSettingsScene` using public [NSHostingSceneRepresentation](https://developer.apple.com/documentation/swiftui/nshostingscenerepresentation), creates the status controller and starts sampling at launch. Closing configuration windows does not stop sampling or quit the app. Termination stops status observation/presentation and sampling; previews do not own sampling lifetime. The public [applicationShouldHandleReopen](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldhandlereopen(_:hasvisiblewindows:)) handler opens or raises native Settings when Finder reopens the already-running app, then returns false to suppress default reopen handling. This provides configuration recovery when available menu-bar space hides the status item.

Providers in `Metrics/` read aggregate CPU ticks, physical-memory/swap counters, and startup-volume capacity. Calculators validate raw inputs and produce immutable Sendable snapshots in `Models/`. Low-level code never appears in views. `Utilities/` formats values centrally. `StatusItemPresentation` builds immutable formatted values and a spoken summary from the selected configuration and current snapshots. `MenuBarLabelLayout.attributedTitle` creates the shared native attributed title for the status item and Settings preview.

The owned `NSStatusItem` uses macOS 27's public [expanded-interface delegate](https://developer.apple.com/documentation/appkit/nsstatusitem/expandedinterfacedelegate) to show and close `StatusPanelPresenter`'s transient `NSPopover`. An `NSHostingController` supplies the SwiftUI controls. After `show` confirms the popover is visible, the presenter activates the application and makes the owned content window key. This gives native transient dismissal focus even when the status item was opened while the agent was inactive. No event monitors or application observers are added. Checkbox changes keep the panel open; clicking elsewhere or opening Settings dismisses it. Popover closure and expanded-session cancellation are synchronized. `LSUIElement` hides the Dock/app-switcher entry. The panel footer is one row containing Settings, the text-only Copy Readings button, and trailing Quit. The panel's bordered Settings Button invokes its dismissal closure, requests `NSApplication.activate()` and calls an injected `OpenSettingsAction` from the represented Settings scene. This retains native mouse, keyboard and accessibility activation. A detached SettingsLink did not open the window during integration testing; no whole-scene environment is copied into the hosting controller. Both the application menu and `SettingsCommands` route Command-comma through panel dismissal, app activation and public `openSettings`; the AppKit menu obtains the action from the represented scene. The final F7khvi UI scenarios passed hosted-panel Settings navigation, native outside-click dismissal and their accessibility assertions; complete assistive-technology and display-matrix review remains separate. The application menu also supplies native Quit, Close Window, Copy and Select All commands. No private window lookup, gesture-only hook or delayed retry is involved. Quit uses normal application termination. Settings alone owns presentation of the native Privacy and Metric Help sheets. The panel no longer owns Help presentation state or an About action. There is no persisted hidden-status-item state, launch-at-login helper, deep link, or background service.

## Concurrency and lifetime

`MetricsStore` is main-actor observable state. Its owned utility-priority task starts off-main and owns two result-discarding child loops: CPU/memory and storage. Providers run synchronously off-main; publication hops to the main actor. Each Mach host send right is released with `mach_port_deallocate`.

CPU and memory refresh approximately every two seconds. Storage refreshes every 30 seconds after a valid read and retries every two seconds when unavailable. Suspensions use cancellable task sleeps. Weak captures prevent the task from retaining the store; deinitialization cancels work. No timer array, sample queue, chart buffer, or history accumulates.

Each start creates a sampling identity. `stop()` invalidates it immediately and cancels the task; publication checks identity and cancellation on the main actor. Thus a synchronous read that finishes after stop/restart cannot overwrite the next generation. `stop()` returns the cancelled task when a caller needs to await cooperative shutdown. System calls already in progress cannot be forcibly interrupted.

CPU discontinuity detection compares sample wall-clock dates. A negative gap or a gap above five seconds resets its baseline; the next valid delta restores the reading. This is a sampling-gap heuristic, not a dedicated sleep/wake observer.

Foundation caches resource values on URL instances. The storage provider clears cached values on a local URL copy before each off-main capacity read, ensuring each poll asks for fresh metadata.

## Failure boundaries

A failed CPU call resets the baseline and clears the current value. Initial CPU sampling or zero tick deltas may return no value without a failure log. Missing/throwing memory or storage snapshots clear that category. A missing swap result clears only Swap Used.

Unavailable/recovery transitions are logged once per category with OSLog; samples, errors containing paths, machine identity, and preference payloads are never logged. The UI renders an em dash and an accessible “Unavailable” value. Recovery requires no restart.

## Preferences and presentation

Representation is configured only in Settings, directly below the live preview. The panel retains its metric checkboxes and no longer observes PreferencesStore at its root solely for a display-mode binding; each stat/copy control owns its needed observation.

`MenuBarConfiguration` enforces one to seven unique stats in CPU → Memory → Storage order. Value Only is allowed for one stat; adding another changes it to Compact. Raw persisted identifiers and both earlier preference schemas are preserved. Legacy decoding is live compatibility code, not dead code.

`PreferencesStore` loads app-only JSON from UserDefaults, repairs malformed/wrongly typed values, and immediately persists meaningful changes. Equal assignments skip encoding and disk-preference writes. Unit persistence fixtures use unique suites; interactive tests use the separate launch configuration described below.

`StatusItemController` strongly retains the native status item and observes current snapshots and preferences with an owned main-actor `Observations` task. Each update supplies `NSStatusBarButton.attributedTitle` with the shared title, plus the full app-name/metric-summary accessibility label/title and a tooltip. Labels/static separators use the system font and values use `NSFont.monospacedDigitSystemFont`. All Compact runs use `smallSystemFontSize` (11 points on the reviewed runtime); other modes use `systemFontSize` (13 points). `MenuBarLabelView` supplies only the Settings preview, using the same `StatusItemPresentation` and native attributed-title builder. It explicitly converts both NSFont and kerning attributes to the SwiftUI attribute scope. `MenuBarLabelLayout` formats candidate strings and resolves the visual percent-gap strategy once per locale, then caches separate point columns for normal and Compact fonts: the largest decorated percentage from 0 through 100, and separate memory/storage widths from localized repeated-digit and zero-heavy numeric templates combined with all seven byte suffixes. Every category also includes the unavailable marker. Compact uses a single space between complete stat slots; other modes use two. The native title and point-width calculation use the same locale, value columns, prefix fonts and separators. Older character-count formatter helpers remain for their plain-text contract and tests; they no longer determine native geometry. See [ADR-020](DECISIONS.md#adr-020--use-native-tabular-digits-and-measured-value-columns).

`MenuBarLabelLayout` measures static prefixes/separators in their actual font and adds the cached point columns for the active mode's font size. Each reading has one ordinary leading space with kerning `max(0, reservedWidth - measuredValueWidth) - spaceAdvance`, filling its unused column width independently of digit, unit or unavailable-marker width. Value runs explicitly start with zero kerning, disabling pair kerning before any percent decoration. `makePercentSpacing` inspects the locale's formatted 100% once through public Core Text glyph positions and string indices. It finds the visible percent glyph and neighboring numeric edge, excludes Unicode format marks, and skips decoration when locale whitespace already separates them. It caches the visible symbol plus the symbol/first-number/last-number boundary and applies two points to exactly one visible character for subsequent values. The full percentSymbol may include an Arabic Letter Mark; kerning that entire string would decorate the marker as well and can double the gap. The measured columns include the final decoration while formatted text, locale spaces, prefix symbols and bidirectional marks stay intact. The total reservation is independent of current readings. The status controller assigns a positive [NSStatusItem.length](https://developer.apple.com/documentation/appkit/nsstatusitem/length), including 16 points for native button padding, only when selection, display mode or locale changes. Its owned locale-notification task refreshes layout and restarts presentation observation. Live values change the title without requesting a new allocation. Both observation tasks use weak captures and are cancelled at shutdown. There is no status image cache or app-imposed width cap. Fixed allocation must still be checked against actual glyphs and screen frames; it cannot create room on a crowded or notched display. Apple documents that [isVisible](https://developer.apple.com/documentation/appkit/nsstatusitem/isvisible) remains true when insufficient space temporarily hides an item, so it is not an overflow detector.

Settings presents the same full text in a focusable horizontal ScrollView with native scroll indicators and guidance on seeing the complete selection. `PrivacyInformationView` presents static, localization-ready descriptions of aggregate reads, local preferences, current-only readings, absent network features, and category-only diagnostics. Its scrollable content and Done/Return/Escape dismissal require no provider, persistence, or network work. Keep these descriptions synchronized with changes to data handling. Descriptive names and accessibility text use localization-aware APIs; compact status codes retain their current English contract. No translations are bundled yet.

`LaunchAtLoginStore` reads the real OS registration state through an injected MainActor `LaunchAtLoginServicing` boundary. `MainAppLoginService` wraps public `SMAppService.mainApp`, without a helper or extra entitlement. Only an explicit toggle registers or unregisters the app. Initialization and Settings activation refresh status without registration. Pending approval is displayed explicitly and links to Login Items in System Settings. The store serializes registration work in an owned task with a weak store capture, then rereads OS state; failures show sanitized guidance. There is no shadow UserDefaults flag, and Restore Defaults affects only menu-bar preferences.

`CurrentReadingsFormatting` is a nonisolated formatter for full selected names and locale-aware values. The Copy Readings button reads current immutable snapshots synchronously on the main actor before formatting, then writes the text using `NSPasteboard`. On success the same button displays Copied and posts an accessibility announcement. Its label reserves space for both localized strings using hidden text in a ZStack, so feedback does not change the button footprint. A native alert reports failure. It does not read previous clipboard contents or retain a history. The OS owns the copied content after the write, including any enabled Universal Clipboard behavior. `MetricHelpView` explains existing definitions and update behavior using local, selectable, scrollable text presented from Settings. See [design](DESIGN.md) for accessibility validation constraints.

## Configuration and tests

All targets use macOS 27 and Swift 6. The app additionally uses MainActor default isolation. Debug is unoptimized/testable; Release uses standard whole-module optimization, dead-code stripping, and asset space optimization. Both source app configurations enable sandbox and hardened runtime. The current Debug development build resolves hardened runtime to NO while Release resolves YES; the validation helper reports this distinction and requires the Release setting. Effective shipping hardening still requires final signature review.

`UITestLaunchConfiguration` and its delegate initialization are guarded by `#if DEBUG`. An explicit `CORE_METRICS_UI_TESTING=1` launch uses a dedicated UI-test UserDefaults suite. It resets that suite and starts with one Value Only statistic unless `CORE_METRICS_UI_RELAUNCH=1` requests preservation of the test preferences. The optional `CORE_METRICS_UI_APPEARANCE` flag applies light or dark appearance to this application through public AppKit APIs. Normal launches retain standard preferences and system appearance; Release excludes these test hooks. Providers acquire real aggregate metrics during normal UI scenarios. Only the focused position regression enables `CORE_METRICS_UI_ALTERNATING_CPU=1` to inject a DEBUG-only CPU provider alternating 9% and 100%; memory and storage remain live. It observes six actual status publications and compares the native item's width and screen position, then confirms the panel opens, closes with Escape and reopens. A separate async UI test calls public `NSWorkspace.openApplication` on the already-running app, requires an unchanged process identifier, and checks that Settings becomes foreground and usable. Login registration uses a DEBUG fake service, and clipboard writes use injected success/failure closures (`CORE_METRICS_UI_COPY_FAILURE`), leaving real login items and the general clipboard untouched. A unit test separately exercises a private named pasteboard and releases it afterward. The dark seven-stat scenario adds selections through the panel, then relaunches with the saved test preferences to exercise status-item availability and its full accessible summary at startup. A focused Settings test adds two stats to the initial selection in Label and Value mode, checks the complete status names and growth of the native frame, then verifies the selections after closing and reopening Settings. Available menu-bar space still varies by desktop configuration; test outcomes belong in the report.

The main shared scheme builds the app and unit tests. The separate UI scheme builds the app and XCTest runner. Native status-item accessibility assertions must inspect the button's exposed title/label and verify complete metric context. The final F7khvi desktop run passed all eight UI scenarios with no failures. Debug/Release builds, 68 unit-test declarations with 161 executions, analysis, configuration and source/packaged artifact checks passed, as did the separate ad-hoc-signed Release build. The live geometry fixture and native outside-click regression both passed. Known toolchain and beta-runtime diagnostics remain documented separately from those passing checks. The report retains individual results and the wider runtime limits. Provider protocols permit deterministic fixtures; Swift Testing covers calculations, migrations, persistence, cancellation, recovery, formatting, and cached resource invalidation. See [DEVELOPMENT.md](DEVELOPMENT.md) for validation commands and [PROJECT_ANALYSIS_REPORT.md](PROJECT_ANALYSIS_REPORT.md) for measured results.
