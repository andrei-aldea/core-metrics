# Design and accessibility

Core Metrics is a restrained native Mac utility. The menu bar is the primary surface; its persistent panel and Settings configure the values. There is no mobile layout, dashboard chart, process list or optimizer UI.

## Visual contract

- Use system typography, semantic monochrome colors, native controls, SF Symbols and platform spacing. Selection is visible through checkboxes and labels, never color alone.
- The status item presents native live text for one to seven selected stats in CPU → Memory → Storage order. It shows no branded header. Supply the full selection without an app-imposed width cap; Settings provides a scrollable preview of every selected value.
- Label and Value, Compact, and single-stat Value Only are the supported modes. Names/short codes stay recognizable; values use locale-aware digits, zero-decimal percentages, and one-decimal byte units.
- Use measured point columns: decorated localized percentages 0…100, and byte-width templates across all seven suffixes, including Unavailable. An ordinary leading space with calculated kerning fills each value's unused column width. Compact separates stats with one space; other modes use two.
- Reserve numeric space independently of live readings. Measure decorated locale glyph widths; character-count padding does not determine native geometry. Keep the positive native status-item allocation unchanged between samples; recalculate it when selection, mode or locale changes.
- Use native `NSStatusBarButton.attributedTitle`: system font for labels/static spacing and the standard system font with tabular digits for values. Compact uses a uniform small system size for codes, separators and values (11 points on the reviewed runtime); other modes use the normal system size (13 points). Measure static runs in their actual font and add point columns cached separately for each font size and locale. Candidate strings and the visual percent-gap strategy are prepared once per locale; the two-point gap remains the same in every mode. Add a two-point visual percent/digit gap only when locale whitespace does not already provide one. Resolve the visible edge from Core Text once per locale and kern one visible character, excluding format marks; preserve existing spacing, symbol order and bidirectional text. The Settings preview explicitly converts both fonts and kerning. `NSStatusItem.length` owns the actual width allocation. Check typography, complete readings, width and screen position as values change; a calculated reservation alone does not establish runtime correctness.
- macOS owns the native popover material and SwiftUI Settings chrome; the preview uses the native glass modifier. Do not stack custom blur layers or imitate system glass.
- There are no continuous animations, charts, decorative cards, progress bars, or color severity scales.

## Naming

Use **Used** consistently in statistic names. Full names say **Memory** and **Storage**; the app does not determine whether the startup volume uses SSD hardware. Preserve the familiar Wired Memory, Compressed Memory, Cached Files, Swap Used and Physical Memory names. Settings and selection controls distinguish byte amounts from **Memory Used (%)** and **Storage Used (%)**. Within category sections, omit redundant category prefixes: Used, Used (%), Free and Total. CPU Used, User, System and Idle are all percentages.

The status label uses the full names, except Memory Used (%) and Storage Used (%) use the base labels Memory Used and Storage Used because their live values already include the percent sign. Compact codes remain unchanged. Full names still identify percentages in copied readings and accessibility summaries. Longer names need runtime width review; preserve complete text and the compact alternative.

## Surfaces and layout

The status panel begins with CPU, then Memory and Storage checkbox sections. Its single footer row places Settings beside the text-only Copy Readings button, with Quit at the trailing edge. About and Metric Help are absent from the panel. The panel contains no Menu Bar Text heading or representation picker; the space is available for its scrollable metric choices. Changing a stat keeps the panel open. No live number is duplicated beside each selector.

A transient native popover hosts the panel and closes when the person interacts elsewhere. Successful presentation activates the app and makes the owned content window key, giving native dismissal focus even when the agent started in the background. Interior selection changes keep it open. The panel has a 420-point normal width and a 500-point accessibility-size branch. Its grouped form can scroll. Settings has a 520-point minimum width, a horizontally scrollable live preview of the full selection, Menu Bar Text choices immediately below it, selected rows with remove buttons, an Add Stat menu, optional Launch at Login, Privacy, Metric Help and Restore Defaults. The preview participates in keyboard focus, retains native scroll indicators, and explains horizontal scrolling. Test actual macOS text/display settings; a SwiftUI dynamicTypeSize branch alone does not prove desktop large-text support.

The panel's native Settings Button dismisses the popover, requests application activation, then calls an injected `OpenSettingsAction` from the represented Settings scene. Command-comma follows the same sequence through native application/Settings commands. The app registers the SwiftUI Settings scene through Apple's public scene bridge; the AppKit menu invokes that scene's public `openSettings` action. Clicking Settings or using Command-comma should open or raise the native Settings window in front; testing must not activate the app afterward to make this work.

Privacy opens a native sheet with semantic headings and selectable, wrapping text. Its content can scroll and receive keyboard focus; Done remains outside the scrolling area. Return and Escape dismiss the sheet. The content explains the implemented local data handling without inventing publisher contacts, public URLs, or legal guarantees. Public release-policy and support requirements remain in [APP_STORE.md](APP_STORE.md).

Metric Help is a native sheet available only from Settings, with the same scrolling, selectable text, semantic headings, and Done/Return/Escape behavior as Privacy. It explains the app’s current definitions without implying that all memory categories add together or that used percentage measures memory pressure. Copy Readings includes full selected names and locale-aware values. Its button label becomes “Copied” after success, while space reserved for both localized labels keeps the footer stable. The button has no icon or separate confirmation caption. Every successful copy posts a spoken accessibility announcement; failure presents a native alert whose explicit OK action clears the error. Closing the panel also clears that alert state so reopening cannot restore a stale error. Copying runs only when requested.

Launch at Login starts off for an unregistered app. The toggle reflects macOS state, disables during a registration change, and displays pending approval or unavailable states in text. Approval and errors offer a native System Settings action. Restore Defaults resets menu-bar choices only.

macOS manages available menu-bar space. Long selections may not fit on crowded desktops or beside a notch; Compact mode or fewer selections require less room. The app supplies every selected reading, while Settings and Copy Readings provide the full selection independently of available status-item space. Wider localized glyphs consume additional real space. Reopening the already-running app in Finder opens native Settings so the person can choose Compact or fewer stats even when the status item is hidden.

## Failure and accessibility semantics

An unavailable provider clears its old value and displays an em dash; VoiceOver says “Unavailable.” CPU needs an initial baseline before showing a delta, and unavailable swap does not hide valid physical-memory values.

The native status button receives “Core Metrics” and the full metric/value summary as its accessibility label and title; the Settings preview shares that summary. Inspect the actual attributes and verify spoken output in the running app. Do not infer spoken content from the rendered abbreviated title alone. Panel checkboxes expose full metric context to distinguish, for example, Memory Used (%) from Storage Used (%). Native selection state remains available. Remove controls identify their stat and explain when at least one selection must remain. Decorative short codes in Settings are hidden from accessibility.

Descriptive strings use localization-aware APIs and existing SwiftUI extraction. There are no bundled translations yet. Compact menu-bar abbreviations intentionally retain their established English spelling; translation requires width and meaning review. Number formatting accepts the locale without inventing translated content.

## Required runtime review

Verify real outside clicks in another application and on the same-app Settings window, dismissal and reopening, interior selection persistence, and Escape. Verify status selection, one/seven boundaries, persistent-panel behavior, canonical ordering, all three modes, Settings opening/closing, immediate updates and horizontal preview. Check the single footer row, absence of panel About/Metric Help, text-only copy control, and unchanged button footprint after “Copied” feedback. Check native typography and complete readings with one, three and seven selections, the accessible summary, and stable status width and screen position across several sampling updates with an unchanged configuration. Verify that adding/removing stats and changing mode or locale recomputes the allocation. Distinguish space imposed by macOS from missing application content. Reopen the already-running app through Finder and verify that Settings opens without depending on status-item visibility. Exercise login toggling and approval/error guidance, explicit copy success/failure, and Metric Help in Settings. Exercise Privacy opening/reopening, vertical scrolling, Done/Return/Escape dismissal, and focus restoration. Check keyboard traversal/scrolling, VoiceOver navigation and focus, labels/values/hints, light/dark appearance, Increased Contrast, Reduce Transparency, Reduce Motion, Differentiate Without Color, supported larger text, constrained windows and long locale glyphs.

Interactive test launches use an isolated preferences suite and an application-only appearance override compiled into Debug. The dark seven-stat scenario adds selections after opening the panel, then uses an explicit test relaunch flag to preserve them and exercise startup. Alongside the broad light and dark flows, a focused Settings test adds Memory Used and Storage Free in Label and Value mode, verifies all three status names and width growth, and closes and reopens Settings to check the selections. A focused DEBUG-only CPU fixture alternates 9% and 100% to compare actual status-item width and screen position across six publications, then opens the panel, dismisses with Escape and reopens it. The separate async NSWorkspace reopen fixture verifies an unchanged process and usable Settings. The final F7khvi desktop run passed all eight scenarios with no failures, including three full-name stats, seven Compact stats and six alternating live-value frames with unchanged geometry.
